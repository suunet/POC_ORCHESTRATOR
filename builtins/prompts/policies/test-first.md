# テストを先に書く

P5は2つのstepに分ける。

## p5-test

- 指示書の§4.2（受入条件）と§4.3（テストケース）に挙げたテストだけを書く。挙がっていないテストが必要だと気づいたら、書かずに`notes`で知らせる
- 受入条件のテストは、テストの名前かコメントに受入条件のID（`UC-NNN-AC-NN`）を入れる
- 実装のコードは書かない
- 新しいテストが失敗することは、gateflow がこのstepの後にテストを実行して確かめる

## p5-implement

- p5-test で書いたテストのファイルは変更しない。テストが誤っていると判断したら、変更せずに`test_defect`を報告する
- テストを通す最小限の実装をする
- §4に挙げていないファイルの変更が必要なら、変更せずに`blocked`を報告する
- P5で更新してよい文書は、§4.4に挙げたシートだけ
