# カタログ

〈プロジェクト名〉の要件の正本。要素の種類ごとに1ファイルで管理し、ファイル間はIDで関連付ける。標準の構成とIDの定義の場所は、gateflowの組み込みのひな形と`.gateflow/project.json`の`ids`による。

## IDの書き方

gateflow の ID 整合チェックは、次の書き方を前提に読む。守らないと、参照を見落としたり、誤って指摘したりする。

- 参照は`ID（名前）`の形で書く。括弧は全角の「（」「）」にする。半角の`()`は名前とみなさず、名前の検査の対象にならない。括弧の中に括弧を入れてよい
- ID の直前に英数字・`_`・`-`があると、ID とみなさない（例：`XABC-001`）。ID の直後に英数字があっても、ID とみなさない（例：`ABC-0021`は`ABC-002`と読まない）。日本語の文字は区切りになるので、ID の前後に続けて書いてよい
- 子の ID（例：状態の`STM-NN.状態名`）は、親の ID、区切りの文字、子の名前の順に書く。子の名前は、定義済みの名前のうち最も長く一致するものとして読むので、名前の後に続けて文を書いてよい（例：`STM-NN.公開へ`）
- 子の名前には、空白、`|`、`` ` ``、全角と半角の括弧、`、`、`。`、`,`、`・`、`[`、`]`、`「`、`」`、`:`、`：`を使わない。定義にない名前は、これらの文字の手前までを名前とみなして「定義されていない」と指摘する
- 子の名前の列のうち、空のもの、`—`、`-`、全角の括弧で始まるもの（例：「（初期）」）は、子の定義とみなさない
- 定義は表から読む。コードブロック（```` ``` ````や`~~~`）の中の表は定義として読まないが、コードブロックの中の ID は参照として数える
- 表のセルの中のバッククォートは、必ず閉じる。閉じないと、その行の残りの`|`がセルの区切りとして読まれない
- 廃止した定義は行を残し、行のどこかのセルを`project.json`の`ids.deprecatedMarker`（例：「廃止」）で始める。廃止した ID を参照すると、必須の指摘になる
